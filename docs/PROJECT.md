# 项目说明：把视频收藏变成可检索的素材库

## 从什么问题开始

短视频平台的收藏通常只能靠标题和封面辨认。创作者可能记得视频里的一句话，却不记得标题，只能反复重看。大量素材混在一起，后续想只分析几条视频时也难以明确范围。

这个项目把“发一个分享链接”转成一篇普通本地笔记：封面、来源、发布时间、点赞快照、真实文字稿放在一起，能按口播关键词搜索，再按用户用途分类。Obsidian是可选的阅读与筛选界面，文件本身不依赖AI或专有数据库。

## 流程与分工

```mermaid
flowchart LR
  A[分享链接或整段分享文案] --> B[核对目标视频与资料]
  B --> C{有可用中文字幕?}
  C -->|有| D[提取并检查字幕]
  C -->|没有| E[取得真实音频并本地识别]
  E --> F[核对首中尾和疑似漏句]
  D --> G[保存Markdown和封面]
  F --> G
  G --> H[按用户规则分类和检索]
  H --> I[固定所选清单后分析]
```

链接解析、保存、去重等重复步骤由辅助程序执行。智能体负责读取用户规则、选择可用工具、处理例外、核对真实内容和整理摘要。无字幕后备和分类不宣传为纯脚本全自动完成。

## 项目发起者的工作

- 从自己搜不到收藏视频的经历中识别需求，确定必须保存的字段与全文检索目标。
- 设计“标题 — 作者”的文件名、可自定义的分类规则，以及只分析选定视频的清单机制。
- 使用AI辅助实现与迭代，通过真实链接、重复收纳、中文编码、音频转写和跨宿主试用验收结果。
- 区分程序测试、真实样本成功和人工辅助后备；要求没有真实文字稿就不能报成功。

代码与说明由AI协助完成。项目展示应如实强调需求识别、流程设计、样本测试和验收，不包装为独立开发全部底层模型、保证全平台兼容或独立完成工程团队工作。

## 已验证与尚未验证

实际证据见 [发布验收报告](RELEASE_TEST_REPORT.md) 和 [兼容性记录](../references/compatibility.md)。测试数量是程序检查数量，不是视频样本数量；自制音频不等于真实无字幕小红书链接已自动跑通。

目前重点是小红书本地收纳。平台验证、网络和页面变化可能导致失败；音频识别也可能漏字。抖音只有人工辅助经验，豆包、Windows/Linux与陌生用户盲测按报告标注状态。
